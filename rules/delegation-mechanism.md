# Claude CLI 托管机制

本机制把 6 个 Claude CLI 从“并排开的窗口”改造成“主控 + 看板 + 验收”的工作流。目标是更高效地使用会话，同时遵守 `CLAUDE_CLI托管准则.md`。

## 三层结构

1. 本机事实源：Claude Code 的 `.jsonl` 会话记录、项目代码、日志、任务产物。
2. 本地管理层：`CLAUDE_CLI托管看板.md`、本机制文档、单轮日志、交接包。
3. 云端摘要层：从 `templates/云看板_脱敏模板.md` 复制出去，只同步脱敏状态。

## 角色分工

- 主控窗口：统一调度、拆任务、决定下一步。
- 观察窗口：只读进度、日志、状态。
- 验收窗口：检查产物是否正确，不继续扩展新任务。
- 暂停窗口：保留上下文，不推进。

## 每轮操作流程

1. 读取 `CLAUDE_CLI托管看板.md`。
2. 选择一个窗口作为本轮唯一活跃对象。
3. 生成本轮目标和单步动作。
4. 判断是否需要用户确认。
5. 执行或等待用户执行。
6. 验收结果。
7. 更新看板和单轮日志。
8. 必要时生成交接包。

## 云文档使用方式

云文档只做管理视图，建议字段来自 `templates/云看板_脱敏模板.md`。

当前云端目标：

- 语雀知识库：`https://www.yuque.com/bowenlianghua/rne5mx`

同步前必须检查：

- 是否包含 token、cookie、API key、密码、私钥。
- 是否包含完整 transcript。
- 是否包含可直接恢复账号访问的 session 凭据。
- 是否包含不该外传的完整路径、日志、业务数据。

如需我代为上传或写入云文档，必须先说明上传字段、目标平台和用途，并取得用户确认。

## 高效范式

- Context Engineering：维护“当前真实状态”，不把全部历史塞进上下文。
- Session Ledger：每轮都有短日志，记录动作、结果、风险、下一步。
- Handoff Packet：跨窗口或跨模型时用交接包，不重读全部历史。
- Single Active Agent：默认只推进一个 Claude CLI，其他窗口做上下文和验收。
- Human-Paced Automation：像人工一样读结果、判断、再推进，不做无间隔循环。

## 文件清单

- `CLAUDE_CLI托管准则.md`：行为边界。
- `claude_cli_policy.json`：机器可读策略。
- `CLAUDE_CLI托管看板.md`：当前 6 窗口状态。
- `CLAUDE_CLI托管机制.md`：本机制说明。
- `templates/云看板_脱敏模板.md`：可复制到云文档的脱敏模板。
- `templates/单轮会话日志模板.md`：每轮记录模板。
- `templates/交接包模板.md`：恢复/交接模板。
